Go는 수동 메모리 해제가 없지만, GC가 언제 어떻게 도는지 정도는 알아둘 필요가 있다.

## 동시성 마크-스윕 GC

Go의 GC는 애플리케이션 실행과 대부분 동시에 진행되는 tri-color mark-and-sweep 방식이다. STW(Stop-The-World) 구간을 짧게 유지하는 데 초점을 맞춰 발전해왔다.

## GOGC로 트레이드오프 조정

```bash
GOGC=200 ./myapp
```

`GOGC`는 다음 GC가 도는 시점을 힙 증가율로 결정한다. 기본값 100은 힙이 두 배가 될 때마다 GC를 도는데, 값을 올리면 GC 빈도는 줄지만 메모리 사용량이 늘어난다. 메모리보다 지연시간이 중요한 서비스라면 값을 올려보는 것도 방법이다.

## 프로파일링으로 확인하기

```go
import _ "net/http/pprof"
```

`pprof`를 붙여두면 `/debug/pprof/heap`으로 실제 힙 스냅샷을 떠서 어디서 메모리를 많이 잡고 있는지 확인할 수 있다. 감으로 튜닝하기 전에 먼저 측정부터 하는 게 순서다.
