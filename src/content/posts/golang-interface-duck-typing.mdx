Java의 `implements` 키워드에 익숙하다면 Go의 인터페이스가 처음엔 이상하게 느껴질 수 있다.

## 암묵적 구현

```go
type Writer interface {
    Write(p []byte) (n int, err error)
}

type FileLogger struct{}

func (f FileLogger) Write(p []byte) (int, error) {
    fmt.Print(string(p))
    return len(p), nil
}
```

`FileLogger`는 `Writer`를 구현한다고 어디에도 선언하지 않았지만, `Write` 메서드 시그니처가 일치하기 때문에 `Writer` 타입 자리에 그대로 쓸 수 있다.

## 작은 인터페이스가 좋은 인터페이스

표준 라이브러리의 `io.Reader`, `io.Writer`는 메서드가 딱 하나뿐이다. 인터페이스를 크게 만들수록 구현 부담과 테스트용 mock 작성 비용이 커지므로, 꼭 필요한 메서드만 모아 작게 쪼개는 게 Go의 관례다.

## 빈 인터페이스와 any

```go
func Describe(v any) {
    fmt.Printf("(%v, %T)\n", v, v)
}
```

Go 1.18부터 `interface{}` 대신 `any`를 쓸 수 있다. 다만 타입 안정성을 포기하는 트레이드오프이므로 제네릭으로 대체할 수 있는 곳이라면 제네릭을 우선 고려하는 편이다.
