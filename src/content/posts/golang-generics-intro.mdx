제네릭이 없던 시절엔 타입마다 같은 함수를 복사해서 쓰거나 `interface{}`로 타입 안정성을 포기해야 했다.

## 기본 문법

```go
func Max[T cmp.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

Max(3, 5)       // int
Max(1.5, 2.5)   // float64
```

## 제약(Constraint) 정의

```go
type Number interface {
    ~int | ~int64 | ~float64
}

func Sum[T Number](nums []T) T {
    var total T
    for _, n := range nums {
        total += n
    }
    return total
}
```

`~int`처럼 물결표를 붙이면 `int`를 기반으로 정의된 커스텀 타입까지 제약을 만족시킬 수 있다.

## 언제 쓰고 언제 안 쓸지

컨테이너 자료구조나 유틸리티 함수처럼 타입에 무관하게 동일한 로직을 반복하는 곳에는 제네릭이 잘 맞는다. 반대로 타입마다 로직이 크게 달라진다면 억지로 제네릭화하기보다 인터페이스나 그냥 각 타입별 함수를 따로 두는 게 더 읽기 쉬울 때가 많다.
