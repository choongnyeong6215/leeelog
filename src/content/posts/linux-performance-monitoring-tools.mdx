장애가 터졌을 때 대시보드가 없어도 콘솔 몇 줄로 원인을 좁힐 수 있어야 한다.

## CPU와 메모리: top / vmstat

```bash
top
vmstat 1 5
```

`vmstat`의 `r` 컬럼(실행 대기 프로세스 수)이 CPU 코어 수보다 지속적으로 크다면 CPU가 병목이라는 신호다.

## 디스크: iostat

```bash
iostat -x 1
```

`%util`이 100%에 가깝게 오래 유지된다면 디스크 I/O가 병목이다. `await`(평균 대기 시간)도 같이 봐야 실제 지연이 어느 정도인지 감이 온다.

## 네트워크: ss

```bash
ss -tunap
```

`netstat`보다 빠르고 최신 배포판에서 기본 제공된다. `TIME_WAIT` 상태의 커넥션이 비정상적으로 많다면 커넥션 재사용(keep-alive) 설정을 점검해볼 신호다.

## 결론

도구마다 보는 각도가 다르기 때문에, 한 가지 지표만 보고 원인을 단정하지 않는 게 중요하다.
