오랫동안 cron만 써왔는데, systemd timer를 써보니 로그 확인이 훨씬 편했다.

## cron의 장점: 단순함

```
0 3 * * * /usr/local/bin/backup.sh
```

문법이 익숙하고 어디서나 동작한다는 게 여전히 강력한 장점이다.

## systemd timer의 장점: 통합 관리

```ini
# backup.timer
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

`Persistent=true`를 켜두면, 서버가 그 시간에 꺼져 있었더라도 다음 부팅 시 놓친 작업을 실행해준다. cron에는 없는 기능이다. 실행 결과도 `journalctl -u backup.service`로 바로 확인할 수 있어서 별도 로그 파일을 안 챙겨도 된다.

## 선택 기준

간단한 개인 스크립트는 여전히 cron으로 충분하다. 실행 이력 추적, 의존성(`After=`), 동시 실행 방지가 필요한 운영 작업이라면 systemd timer가 더 낫다.
