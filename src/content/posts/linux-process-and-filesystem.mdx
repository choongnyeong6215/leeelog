리눅스 운영을 하다 보면 결국 마주치는 질문은 두 가지다. "이 프로세스는 왜 이렇게 떠 있지?"와 "이 파일은 대체 어디서 온 거지?" 이 글에서는 그 두 질문에 답하기 위한 최소한의 기초를 정리한다.

## 프로세스는 어떻게 태어나는가

리눅스의 모든 프로세스는 `fork()`로 복제되고 `exec()`로 다른 프로그램으로 갈아입는다. 셸에서 명령을 하나 실행할 때도 내부적으로는 이 과정이 반복된다.

```bash
~/Code ❯ ps -ef | head -5
UID          PID    PPID  C STIME TTY          TIME CMD
root           1       0  0 09:12 ?        00:00:03 /sbin/init
root           2       0  0 09:12 ?        00:00:00 [kthreadd]
oracle       842       1  0 09:13 ?        00:00:01 /usr/sbin/sshd -D
oracle      1901     842  0 09:20 pts/0    00:00:00 -bash
```

`PPID` 컬럼을 눈여겨보면 모든 프로세스가 결국 `PID 1`(init 또는 systemd)로 이어지는 트리 구조라는 걸 알 수 있다.

## 프로세스 상태와 시그널

`ps`나 `top`에서 보이는 상태 코드는 생각보다 정보량이 많다.

| 상태 | 의미 | 자주 보는 상황 |
| --- | --- | --- |
| R | Running / Runnable | CPU를 쓰고 있거나 대기 중 |
| S | Sleeping | I/O나 이벤트를 기다리는 중 (대부분의 대기 프로세스) |
| D | Uninterruptible sleep | 디스크 I/O 대기 — 흔히 장애 원인 |
| Z | Zombie | 자식이 종료됐지만 부모가 아직 `wait()`하지 않음 |
| T | Stopped | `SIGSTOP` 등으로 일시 정지됨 |

`D` 상태 프로세스가 쌓이면 대개 스토리지나 NFS 쪽 병목을 의심해야 한다.

```bash
~/Code ❯ kill -l | head -3
1) SIGHUP   2) SIGINT   3) SIGQUIT
```

`kill`은 이름과 달리 대부분 "죽여라"가 아니라 "이 시그널을 보낸다"는 뜻이다. `SIGTERM`(15)은 정상 종료를 요청하는 신호고, `SIGKILL`(9)만이 커널이 즉시 강제 종료시키는 예외다.

## 모든 것은 파일이다 (VFS)

리눅스는 프로세스, 디바이스, 커널 상태까지도 파일 시스템 인터페이스로 노출한다. 이걸 가능하게 하는 계층이 VFS(Virtual File System)다.

```bash
~/Code ❯ cat /proc/842/status | grep -E "Name|State|VmRSS"
Name:   sshd
State:  S (sleeping)
VmRSS:      6520 kB
```

`/proc/<pid>/` 아래에는 해당 프로세스의 메모리, 열린 파일 디스크립터, 환경변수까지 전부 들어 있다. 별도 API 없이 `cat`, `grep`만으로 커널 내부 상태를 들여다볼 수 있는 게 리눅스 운영의 큰 장점이다.

## 파일시스템 용량 계산

ext4 같은 블록 기반 파일시스템의 전체 용량은 블록 크기와 블록 개수의 곱으로 근사할 수 있다.

$$
\text{FS 용량} \approx \text{블록 크기} \times \text{블록 개수}
$$

예를 들어 블록 크기가 4KiB이고 블록이 2,621,440개라면:

$$
4\text{KiB} \times 2{,}621{,}440 \approx 10\text{GiB}
$$

`dumpe2fs -h /dev/sda1` 로 실제 블록 크기와 블록 수를 확인할 수 있다.

## 참고할 만한 명령어 모음

| 목적 | 명령어 |
| --- | --- |
| 프로세스 트리 보기 | `pstree -p` |
| 열린 파일 확인 | `lsof -p <pid>` |
| 디스크 사용량 | `df -h`, `du -sh *` |
| 실시간 리소스 모니터링 | `top`, `htop` |
